# RACE_WEBAPP_LITE

גרסת **LITE** של [`RFID_Race_WebApp`](https://github.com/AdarT96/RFID_Race_WebApp) —
בלי ESP32/RFID, עם שליטת זמן ידנית של המפק״צ והערכה דרך הדפדפן.

- הפורק נעשה מתוך התג [`v1-full-esp32`](https://github.com/AdarT96/RFID_Race_WebApp/releases/tag/v1-full-esp32) של הפרויקט המקורי.
- מסונכרן לאותו Google Sheet של הפרויקט המקורי — שדות שאינם רלוונטיים (EPC, RSSI, אנטנה, הקפות RFID) נשלחים ריקים.

## Quick Start

### 1. הגדרת Firebase

1. פתח [console.firebase.google.com](https://console.firebase.google.com) → צור פרויקט
2. הפעל **Authentication** → Sign-in method → **Email/Password**
3. הפעל **Firestore Database** → Start in production mode
4. פרסם את `firestore.rules` ואת `firestore.indexes.json` (הכללים לפני הפרונטאנד)
5. Project Settings → Your apps → Add web app → העתק את הconfig
6. ערוך את `frontend/js/firebase-config.js` והכנס את הconfig שלך

`firestore.rules` הוא מקור האמת היחיד להרשאות: מפק״צ של הצוות שולט בחיי הסבב,
מעריכים מעדכנים רק מסמך הערכה פרטי בבעלותם, מפקד הגיבוש רואה תפעול בלבד,
ומנהל רשאי לשנות תפקיד/צוות/אישור.
אין להעתיק קטע כללים ישן מההיסטוריה או ממסמך אחר.

### 2. יצירת אדמין ראשון

1. הירשם דרך האפליקציה (עם כל תפקיד)
2. ב-Firebase Console → Firestore → `users` collection → מצא את המסמך שלך
3. עדכן `role = "admin"` ו-`approved = true`
4. עכשיו אפשר להיכנס ולנהל משתמשים אחרים

### 3. Google Sheets

LITE משתמש באותו Apps Script של הגרסה המלאה. אם עדיין לא הוקם:

1. פתח [script.google.com](https://script.google.com) → New project
2. הדבק את תוכן `scripts/Code.gs`
3. הגדר `SHEET_ID` ו-`API_SECRET_KEY`
4. Deploy → New deployment → Web App → Execute as Me → Anyone
5. העתק את הכתובת → הדבק ב-`APP_CONFIG.sheetsApiUrl` בתוך `firebase-config.js`
6. הגדר `APP_CONFIG.sheetsApiKey` לאותה סיסמה סודית

### 4. קבצי אירוע ב־Drive

לכל אירוע נוצרים קבצי צוות וקבצי מעריכים נפרדים. המפתח ברישום הוא
`eventId + team` או `eventId + evaluatorUid`, ולכן מספר צוות או משתמש שחוזרים באירוע
אחר לעולם אינם מקבלים בטעות את קובץ האירוע הקודם. ההקצאה נעשית בשלב האחרון של
`event-setup.html` והיא בטוחה להרצה חוזרת.

לצורכי תאימות, כלי הקבצים הישן בפאנל המנהל נשאר זמין. באירועים חדשים משתמשים במסך
הקמת האירוע, שבו נוצרים רק הקבצים הנדרשים בפועל.

בכל אירוע חדש לכל מעריך נוצר **קובץ Google Sheets נפרד** משלו:

- אישור משתמש או שינוי תפקיד אינם יוצרים קובץ. הקובץ מוקצה רק לאחר שהמעריך שובץ
  לאירוע ובוצע שלב **קבצי Drive** במסך ההקמה.
- הקבצים נוצרים בתיקיית Drive בשם **"קבצי מעריכים"** לצד הקובץ הראשי,
  ונרשמים בטאב **"קבצי מעריכים"** בקובץ הראשי (UID, שם, צוות, קישור).
- בכל סנכרון ל-Sheets, כל שורה נכתבת **גם לקובץ הראשי וגם לקובץ האישי** של
  המעריך שרשם אותה (לפי `evaluator_uid`) — כולל תוצאות תחנה והערות כלליות.
- הכפתורים הישנים ליד רשימת המשתמשים נשארו לצורכי תאימות לקבצים ללא `eventId`;
  אין להשתמש בהם בהקמת אירוע חדש.

**עמודות ה-Sheet (גרסת LITE):** אין יותר עמודות RFID. בטאבי התחנות:
`מקום · ID · זמן(ms) · זמן(mm:ss) · סבב · תאריך · תחנה · מעריך · צוות מעריך · הערות · ציון`
(במקום EPC יש **ID** = מספר משתתף; עמודות אנטנה ו-RSSI הוסרו). בטאב הסיכום הוסרה עמודת EPC.

> ⚠️ אם כבר יש נתונים ישנים ב-Sheet עם עמודות EPC/אנטנה/RSSI — כדאי לנקות את הטאבים
> הישנים לפני שימוש בפורמט החדש, כדי שהעמודות לא יזוזו.

> ⚠️ אחרי עדכון `Code.gs` יש לבצע **Deploy מחדש** ולאשר הרשאות מחדש —
> הסקריפט צריך כעת גם הרשאת Google Drive (יצירת קבצים ותיקיות).

## תפקידים

### מפק״צ (Operator)
שולט בזמן הצוות: **▶ התחל** יוצר סבב חדש ו-**⏹ עצור** מסיים אותו.
הוא נשאר תמיד בסבב האחרון ואינו מנווט אחורה. כל סבב מוגבל ל־40 דקות; בהגעה
לתקרה השעון והפעולות התלויות בזמן נעצרים, והסבב נסגר על ידי המפק״צ באופן בטוח.

### מעריך (Evaluator)
רואה בזמן אמת את הסבב שהמפק״צ התחיל/עצר, אך אינו יכול לשנות את חיי הסבב.
ממשיך לסמן תוצאות, ציונים והערות. בספרינטים ובאלונקה בלבד מוצגים טאבים נגללים של הסבבים;
המעריך יכול לעבור ביניהם ולחזור בלחיצה לסבב הפעיל. רשימת סדר ההגעה ניתנת לסידור מחדש
גם אחרי עצירה וגם בסבבים היסטוריים. לכל מעריך סדר, ציונים, מדידות והערות פרטיים משלו;
שינוי אצל מעריך אחד אינו גלוי לאחר. זמני הגעה נשמרים פנימית למחקר אך אינם מוצגים בממשק.

בתפריט **מועמדים** כל מעריך מקבל דשבורד אישי: ממוצע נוכחי לכל תכונה, לשוניות תחנה,
גרף מקומות ועריכת נתוני המקור. מפק״צ אינו רואה ציונים או תוצאות הערכה ורואה רק הערות
כלליות שהוא עצמו כתב.

### מפקד הגיבוש (Formation Commander)
תפקיד גלובלי ללא צוות. רואה בדשבורד נפרד כמה מועמדים פעילים ונשרו, מצב כל צוות
והתחנה האחרונה שלו, התפלגות סיבות נשירה והמלצות פתוחות של מפק״צים. הוא יכול לאשר
או לדחות המלצה, לסמן נשירה ישירות ולהחזיר מועמד לפעילות. אין לו גישה לציונים,
סדרי הגעה או הערות פרטיות של מעריכים. למפקד הגיבוש ולמנהל יש שליטה מלאה בלו״ז־העל;
שמות מפקדי הצוותים בלו״ז מוזנים ידנית ואינם משנים משתמשים או הרשאות. לחיצה על תחנה
פותחת מצב תפעולי בלבד—צוות, מסלול, מצב וסבבים—ולא את מסך ההערכה. פרטי זהות של מועמד
נפתחים רק לאחר לחיצה מפורשת על המועמד. חיפוש מועמד עובד לפי מספר, שם או תעודת זהות;
מרכז החריגות מרכז תקרת זמן, סבבים מקבילים, שיבוץ חסר, מידע מועמד חסר, המלצות נשירה
ודיווחי תקלה פתוחים בלי לחשוף נתוני הערכה.

## אירוע גיבוש ומצב מועמד

- מנהל פותח **טיוטת אירוע** דרך `event-setup.html`. הטיוטה נשמרת אחרי כל שלב ואינה
  משנה את האירוע הפעיל: שם → לו״ז וצוותים → מועמדים → אנשי צוות → קבצי Drive ובדיקת מוכנות.
- אפשר להעלות לו״ז וקובץ מועמדים ב־Excel/CSV. המתאמים ממירים את הקובץ למודלים
  הקנוניים ורק אז מפעילים את אותן בדיקות ושכבות שמירה של העריכה הידנית.
- מספר מועמד ולו״ז תקין הם תנאי מבני. שם, תעודת זהות, טלפון חירום, כשירויות,
  תקן סגל וקבצי Drive חסרים מוצגים כאזהרות ואינם חוסמים הפעלה.
- ההפעלה מפרסמת תחילה גרסת לו״ז מלאה, ואז מעדכנת אטומית את האירוע,
  `settings/activeEvent` והקרנת התפקיד/צוות של אנשי הסגל. בכניסה, הלקוח מאמת את
  השיבוץ האירועי ומונע ממשתמש שהוסר מהסגל להיכנס למסכי התפעול. ניתן להמשיך לערוך לאחר מכן.
- סבבים חדשים משויכים ל־`eventId`. נתוני ניסוי ישנים נשארים ללא שינוי אך אינם
  נכנסים לדשבורד או לסבבים של האירוע החדש.
- מפק״צ יכול בעמוד המועמד לשלוח המלצת נשירה עם אחת משלוש סיבות בלבד:
  **פרישה, רפואי, הדחה**. ההחלטה נשארת בידי מפקד הגיבוש.
- נשירה מסירה את המועמד רק מצילומי המשתתפים של סבבים חדשים. סבב שכבר נוצר נשאר
  היסטורי ואינו משתנה בדיעבד. שינוי סטטוס נשמר גם ביומן מעברים בלתי ניתן לעריכה.

### מנהל (Admin)
- אישור/דחייה של משתמשים חדשים
- שינוי תפקידים
- צפייה בהיסטוריית מירוצים
- צפייה בדיווחי תקלות, שינוי סטטוס והוספת הערת טיפול פנימית
- הסבה חד־פעמית ומבוקרת של נתוני הערכה ישנים למבנה פרטי
- **בגרסת LITE:** ניהול משתתפים לכל צוות + עריכת שמות התחנות לכל צוות
_(הפאנל LITE יורחב בשלב הבא של הפיתוח.)_

## Deploy

הגרסה נדחפת כרגע ידנית. `.github/workflows/deploy.yml` (GitHub Pages CI/CD) הוסר בעת יצירת ה-repo — יוחזר כשייקבע יעד ה-hosting.
ה־workflow `validate.yml` אינו מפרסם; הוא מריץ בדיקות מבנה סטטיות, בדיקות לוגיקה
ובדיקות הרשאות Firestore בכל PR ובכל push ל־`master`. ה־workflow משתמש ב־Node 22
וב־Java 21, מוגבל בזמן ומבטל ריצה ישנה כאשר עולה commit חדש לאותו ענף.

בהשקה הראשונה של מבנה ההערכות הפרטי: מפרסמים קודם את `firestore.rules`, אחר כך את
ה-frontend, ורק אז מפעילים בפאנל המנהל את **הסבת פרטיות הערכות** בזמן שאין פעילות.
הכלי ארכיוני וניתן לחידוש; אין ליצור ידנית את סמן ההסבה.

## מבנה נתונים ב-Firestore

- **`users/{uid}`** — משתמשים (`role`, `team`, `approved`); למפקד הגיבוש התפקיד `formation_commander` ו־`team: null`.
- **`teams/{teamNumber}`** — מנוהל על ידי המנהל בפאנל. כולל:
  - `candidates` — מערך מועמדים `{ participantId, firstName, nationalId, emergencyContactPhone, doctorClearance, medicClearance }`. תעודת הזהות והטלפון נשמרים כמחרוזות כדי לשמור אפסים מובילים. כשירות היא קוד מספרי: `0` טרם נבדק, `1` כשיר, `2` לא כשיר.
  - `rosterSource` — מקור הרשימה (`manual|excel`), מזהה מקור, שם קובץ, מועד ומנהל מייבא. עריכה ידנית מתקנת את הרשימה אך אינה מוחקת את מקור הייבוא האחרון.
  - `stationMap` — מיפוי מספרי התחנות לסוגי התחנה של הצוות.
- **`races/{raceId}`** — כל סבב (session) הוא מסמך משלו. `raceId = race_{eventId}_{team}_{station}_{round}`. מבנה:
  - `eventId`, `team`, `station`, `round` — מזהים
  - `status` — `"running"` / `"stopped"`
  - `startedAt`, `endedAt`, `startedBy`, `endedBy` — טיימסטמפים ו-UID
  - `timeLimitSeconds` — תקרת הסבב (2400 שניות); סבבים ישנים בלי השדה משתמשים באותה ברירת מחדל
  - `endedReason` — `"manual"` או `"time_limit"`
  - `participantIds` — צילום רשימת המשתתפים בעת פתיחת הסבב
  - `evaluationSchemaVersion` — `2`; `tags` נשאר ריק ואינו מכיל מידע פרטי
  - **`evaluatorArrivals/{evaluatorUid}`** — מסמך סדר הגעה אישי לכל מעריך: `participantIds`,‏ `order`,‏ `slotTimes`,‏ `completedAt?`. שינוי סדר מחליף משתתפים בין המקומות, בעוד זמני החריצים נשארים קבועים.
  - **`evaluatorAssessments/{evaluatorUid}`** — ציונים, מדידה והערות תחנה של מעריך אחד בלבד. רק אותו מעריך ומנהל יכולים לקרוא.
- **`general_notes/{team_participant}/authors/{uid}`** — הערות כלליות פרטיות לכותב.
- **`settings/evaluationPrivacy`** — סמן השלמת ההסבה; נכתב אוטומטית רק בסיום כלי ההסבה בפאנל המנהל.
- **`issue_reports/{reportId}`** — דיווח תקלה המשויך ל־`eventId`, עם פרטי המדווח והקשר
  תפעולי מאושר בלבד (צוות, תחנה, סבב, גרסה, חיבור ומכשיר). משתמש יכול ליצור; מפקד
  הגיבוש רואה דיווחים פתוחים של האירוע במרכז החריגות, ורק מנהל יכול לעדכן ולטפל.
- **`settings/activeEvent`** — מצביע לאירוע הגיבוש הפעיל וגרסת סכמת הסגל האירועי.
- **`events/{eventId}`** — אירוע והצילום התפעולי שלו:
  - **`teams/{team}`** — צילום רשימת המועמדים ומיפוי התחנות.
  - **`candidates/{team_participant}`** — צילום פרופיל המועמד (זהות, טלפון חירום וכשירויות) יחד עם המצב התפעולי הנוכחי. הפרופיל מוצג רק בדפי מועמד ובדשבורד מפקד הגיבוש; מסכי התחנות ממשיכים לעבוד עם `participantIds` בלבד.
  - **`dropoutRecommendations/{team_participant}`** — המלצת מפק״צ והחלטת מפקד הגיבוש.
  - **`candidateStatusEvents/{id}`** — יומן בלתי ניתן לעריכה של שינויי מצב.
  - **`schedule/master`** — הגרסה שפורסמה לצוותים בלבד: מטריצת לו״ז־העל, שמות מפקדים ידניים, מספרי מסלול ומדיניות עומס.
  - **`schedule/draft`** — סביבת העבודה של המנהל ומפקד הגיבוש. שמירה אינה משנה את הלו״ז הצוותי עד פעולה מפורשת של פרסום.
  - **`teamSchedules/{team}`** — הקרנת לו״ז מצומצמת לכל צוות; סגל צוותי אינו קורא את מטריצת־העל.
  - **`scheduleRevisions/{revisionKey}`** — היסטוריית פרסומים בלתי־ניתנת לשינוי. שחזור יוצר פרסום חדש שמצביע על גרסת המקור; הוא אינו משנה היסטוריה.
  - **`staff/{uid}`** — שיוך תפקיד וצוות לאירוע. באירועים חדשים זהו מקור האמת
    להרשאה; `users.role/team` נשארת הקרנה של האירוע הפעיל לצורכי ניתוב ותאימות.
  - **`artifacts/{team-N|evaluator-UID}`** — מצב הקצאת קובץ Drive של האירוע
    (`pending|ready|failed`), מזהה וקישור. כשל חיצוני ניתן לניסיון חוזר ואינו משחית טיוטה.

פורמט הלו״ז לייבוא רחב ומפורש: `תאריך`, `שעה`, `סוג`, `פעילות`, ואז `צוות 1`,
`צוות 2` וכו׳. תא תחנה הוא `שם תחנה | מספר מסלול`. צבעים ומיזוגי תאים אינם נתונים.
תבנית CSV ניתנת להורדה ממסך ההקמה.

## היסטוריה

- **v0.1-lite** — clone נקי מ-`v1-full-esp32` + הסרת ESP32/RFID.
- **v0.2-lite** — פאנל מנהל: משתתפים לכל צוות + עריכת שמות תחנות פר-צוות (`teams/{teamNumber}`).
- **v0.3-lite** — זרימת מירוץ ידנית: בורר צוות+תחנה, כפתור **▶ התחל תחנה**, grid של משתתפים גדול וידידותי למגע, סימון סיום בלחיצה, רשימה של מי סיים לפי סדר, הערות ותיוגים לכל משתתף, ריבוי סבבים (sessions) פר צוות+תחנה, סנכרון real-time בין מכשירים דרך `onSnapshot`, טיימר מאיות.
- **v0.4-lite** — סנכרון ידני ל-Google Sheets לאותו endpoint של הגרסה המלאה: הכפתור **📊 סנכרן תחנה ל-Sheets** אוסף את כל הסבבים של הצוות+תחנה הנוכחיים, בונה EPC סינתטי בפורמט `TTPPPP` (2 ספרות צוות + 4 ספרות משתתף) שמאפשר ל-`pidFromEpc_`/`teamFromEpc_` ב-Code.gs לחלץ מזהים כרגיל, ושולח שורה אחת לכל משתתף שסיים. `Code.gs` מבצע dedup לפי (epc, round) — לחיצה חוזרת בטוחה.
- **v0.5-lite** — הערות + גרף השוואה:
  - **תיוגים ניתנים לעריכה** — הועברו מ-`APP_CONFIG.commentTags` ל-Firestore `settings/commentTags` (מסמך יחיד עם `tags: [...]`). המנהל עורך בפאנל תחת "💬 תיוגים מהירים למעריכים"; שני הצדדים (מודל הערות תחנה + הערות כלליות) מתעדכנים ב-real-time דרך `onSnapshot`.
  - **הערות כלליות למשתתף** — `general_notes/{team}_{participantId}` = `{ team, participantId, notes: [{ text, authorName, authorUid, at }] }`. סקציה בlite-app.html: בחירת צוות (dropdown למנהל, קבוע לאחרים) + משתתף → הוספה בלחיצה על תיוג מהיר או כתיבה חופשית + מחיקה + סנכרון ל-`SUMMARY_TAB` דרך `handleGeneralNote_` ב-Code.gs.
    - **תצוגה מוגבלת:** מפק״צ/מעריך רואה רק הערות שהוא עצמו כתב (`authorUid == currentUser.uid`); מנהל רואה הכל. הפילטר client-side.
    - **כתיבה מוגבלת:** חוקי Firestore מונעים ממפק״צ/מעריך לכתוב תחת doc-id של צוות שאינו שלהם — בלי קשר למה שקרה ב-UI.
- **v0.6-lite** — UI מוגדל לבחירת משתתפים:
  - **גריד לחיצה במקום dropdowns.** בהערות כלליות המשתתפים מופיעים ככפתורים ריבועיים גדולים (מאותה משפחת CSS של grid הסבב). בחירת משתתף = לחיצה על מספר.
  - **סקציית "💬 הערות לתחנה זו"** ברitri panel של הסבב. picker של משתתפים שסיימו את הסבב הנוכחי בלבד; שמירה ל-`races/{raceId}.tags[i].comments` (מתאפסת בכל סבב חדש). ההערות נשלחות עם שאר הסבב לSheets דרך `📊 סנכרן תחנה ל-Sheets`.
  - **סכימת comments חדשה בתוך `tags[i]`**: מערך של `{ text, authorName, authorUid, at }` (במקום מחרוזות). תאימות לאחור מלאה — הערות ישנות שנשמרו כמחרוזות מנורמלות בקריאה. אותו סינון "רואה רק את שלך" חל גם כאן.
  - המודל של הערות תחנה הישן הוסר; לחיצה על finished pill קופצת עכשיו לסקציית ההערות ומסמנת את המשתתף.
  - **גרף השוואה** — כפתור "📈 גרף השוואה" ב-race panel פותח modal עם multi-select של משתתפים ו-line chart של המקום שהגיעו לכל סבב באותה תחנה (`spanGaps:false` — סבב שלא סיימו בו = פער בקו). ציר Y הפוך כדי שמקום 1 יופיע למעלה.
- **v0.7-lite** — המפק״צ שולט בהתחלה ובעצירה; המעריכים צופים בזמן אמת וממשיכים להעריך. בספרינטים ובאלונקה בלבד נוספו טאבים נגללים למעבר בין סבבים, עם נעילת המפק״צ לסבב האחרון והרשאות Firestore תואמות.
- **v0.8-lite** — ממשק מובייל אדפטיבי לסימון מהיר (עד 9 משתתפים ב־3 עמודות, 10–20 ב־4), רשימת סדר הגעה אנכית עם משתתפים שטרם הגיעו באפור וסידור מחדש בכל סבב, הזנה ידנית בלבד למספר הברגים בעצבים מברזל, סקירת תחנה ברורה, אזורים מובחנים ומתקפלים, ושורת סטטוס/זמן קבועה בגלילה.
- **v0.9-lite** — סדר הגעה אישי לכל מעריך בספרינטים ובאלונקה, גריד מספרים יציב שבו כפתור שסומן נעלם בלי להזיז את האחרים ומופיע מחדש בסבב הבא, השלמה ותיקון גם אחרי עצירה, זמני מקום מבוססי שרת, צילום משתתפים לכל סבב ותאימות לנתוני סדר משותפים מהגרסאות הישנות.

**הערה על מפתח Sheets:** אם `API_SECRET_KEY` ב-Code.gs עדיין בערך ברירת המחדל `YOUR_SECRET_KEY_HERE`, השרת מקבל בקשות ללא בדיקת מפתח. אחרת יש להעתיק אותו ערך בדיוק ל-`APP_CONFIG.sheetsApiKey` ב-`firebase-config.js`.
