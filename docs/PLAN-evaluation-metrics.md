# תכנון — מדדי הערכה 1–7 + הערות מהירות לפי תחנה

מסמך תכנון. מקור האמת לתכנים: `תחנות_מיון.xlsx` (17 תחנות, פרמטרים והערות מהירות).
לא מתחילים קוד עד אישור. עבודה בשלבים על הענף `feat/evaluator-sheet-files`,
כל שלב נבדק ומאושר לפני מיזוג ל-master.

## מטרות (מאושר עם המשתמש)
1. **17 סוגי תחנות**, לכל אחד **1–2 פרמטרים** נבדקים + רשימת **הערות מהירות** משלו.
2. לכל **פרמטר** — ציון **1–7** לכל משתתף בכל סבב.
3. **שומרים הכול**: סדר הגעה (מקום), הסטטיסטיקות הקיימות, וההערות. הציונים מתווספים.
4. **מדידה כמותית לפי סוג התחנה** (שדה `measure`): `"place"` (סדר הגעה — ספרינטים, אלונקה),
   `"reps"` (מספר חזרות — סחיבת ג׳ריקנים, זחילות, מילוי שק), `"none"` (רק ציונים והערות).
5. **כל צוות עובר את כל 17 התחנות**, אך **סדר התחנות שונה בין צוותים**.
   מיפוי `מספר-תחנה ← סוג-תחנה` הוא **דינמי לכל צוות** ונערך בפאנל המנהל.
6. **הפרמטרים וההערות המהירות נערכים בפאנל המנהל** (ברירת מחדל מהקובץ, ניתן לעריכה).
7. **הערות מהירות נכנסות אל תוך ההערות המילוליות** (לחיצה = מוסיפה טקסט מוכן). עד ~10 הערות.
8. **קבצי Drive בתיקייה מרוכזת אחת לאירוע**: `גיבוש <חודש> <שנה>` (למשל "גיבוש אוגוסט 2026").
   אירוע אחד בחודש → תיקייה אחת, נוצרת פעם אחת ומשומשת לכל אורך האירוע (2–4 ימים).

## מודל נתונים

### settings/stationTypes  (Firestore — נערך בפאנל, נזרע מברירת מחדל בקוד)
17 סוגי תחנות. מזהה יציב (id) לכל סוג:
```
{
  "sprints": {
    name: "ספרינטים",
    measure: "place",
    params: [
      { name: "חוסן וכושר הסתגלות",
        quickNotes: ["תנודתיות במיקומים…", "מדווח לא מהימן…", "יציבות/שיפור הדרגתי…", …] }
    ]
  },
  "stretcher": {
    name: "אלונקה סוציומטרית",
    measure: "place",             // רק בחלק האישי
    params: [
      { name: "אקטיביות",           quickNotes: [ … ] },
      { name: "אינטליגנציה חברתית", quickNotes: [ … ] }
    ]
  }
  // … כל 17, כולל: jerrycans, crawls, ironNerves, magen, dynamicFitness, tent,
  //   checkers, spiderWeb, pullup, minefield, sackFill, ladder, puzzleA, debate, discussion
}
```
כל התכנים (שמות פרמטרים + הערות מהירות) ממופים מ-`תחנות_מיון.xlsx` בשלב 1.

### teams/{team}.stationMap  (Firestore — נערך בפאנל)
מיפוי מספר-תחנה של הצוות → מזהה סוג תחנה. סדר שונה לכל צוות:
```
teams/01.stationMap = { "01":"sprints", "02":"debate", "03":"checkers", … "17":"tent" }
```
ברירת מחדל: 01..17 לפי סדר קבוע; המנהל משנה סדר/סוג לכל צוות.

### ציונים (per participant / round / param)
נשמרים לצד ה-tag הקיים במסמך `races` (יחד עם place ו-comments), במבנה:
`scores: { "<paramName>": 1..7, … }`. מתאפס לכל סבב כמו ההערות.

## שינויים לפי קובץ

### app.html — מסך המעריך
- קורא את `stationMap` של הצוות → מזהה סוג התחנה → קורא את `stationTypes[type]`.
- לכל משתתף נבחר, לכל **פרמטר**: בורר **1–7** + שורת הערות מהירות (מוסיפות להערות).
- הערה חופשית + רשימת ההערות שנכתבו (עד ~10).
- `measure="place"` → סימון סדר הגעה; `"reps"` → שדה מספר חזרות; `"none"` → ללא שדה כמותי.
- הסנכרון הקיים (place/סטטיסטיקות/הערות) נשמר; נוסף שיגור הציונים.

### admin.html — פאנל המנהל
1. **עורך סוגי תחנות**: שם, דגל arrivalOrder, פרמטרים (הוספה/מחיקה), והערות מהירות לכל פרמטר.
2. **מיפוי תחנות לצוות**: לכל מספר-תחנה בצוות בחירת סוג מתוך ה-17 (מחליף את שמות-התחנה החופשיים של היום).

### Code.gs — Google Sheet (מבנה סופי: קובץ לצוות · טאב למועמד)
- **קובץ נפרד לכל צוות** (נוצר אוטומטית, נרשם ב"קבצי צוותים" בקובץ הראשי).
- בכל קובץ צוות — **טאב לכל מועמד**: שורה לכל (תחנה × סבב × מעריך).
  עמודות: תחנה · סבב · מקום · מספר · פרמטר א׳ · ציון א׳ · פרמטר ב׳ · ציון ב׳ · מעריך · הערות.
  הערות כלליות = שורת "(הערה כללית)". **כל ההערכות — בלי ממוצע**; idempotent לפי (תחנה×סבב×מעריך).
- **אין קובץ ראשי מרוכז** — הקובץ הראשי מחזיק רק רישומים (קבצי צוותים + קבצי מעריכים).
- **קובץ אישי לכל מעריך** נשמר, באותו מבנה טאב-למועמד, אך רק ההערכות שלו (דרך שיקוף).

### תיקיית Drive
- שם: `גיבוש <חודש בעברית> <שנה>` מחושב מהתאריך ביצירה הראשונה, נשמר ב-`settings` ומשומש שוב.
- כל קבצי המעריכים נכנסים אליה (במקום "קבצי מעריכים" הגנרי).

## שלבי ביצוע (כל שלב = בדיקה ואישור לפני המשך)
- **שלב 1 — תכני ברירת מחדל** ✅: מיפוי כל 17 התחנות (פרמטרים + הערות מהירות) ב-`station-types.js`.
- **שלב 2 — פאנל מנהל** ✅: (א) מיפוי סוג-תחנה לכל מספר בכל צוות (`teams/{team}.stationMap`);
  (ב) עורך סוגי תחנות — שמות פרמטרים, הערות מהירות ומדידה (`settings/stationTypes`).
  ה-app וה-Sheet נגזרים מהעריכות: ה-app טוען מ-Firestore, וה-payload נושא params/measure ל-Code.gs.
- **שלב 3 — מסך המעריך** ✅: ציוני 1–7 לכל פרמטר + הערות מהירות + סדר הגעה מותנה + הערכה בכל רגע.
- **שלב 4 — סנכרון Sheet** ✅: **קובץ לכל צוות, טאב לכל מועמד**, שורה לכל
  (תחנה×סבב×מעריך) — כל ההערכות בלי ממוצע. אין קובץ ראשי מרוכז; קבצי מעריכים נשמרים
  (טאב-למועמד עם הערכותיו בלבד). idempotent. אומת בסימולציה.
- **שלב 5 — תיקיית Drive** ✅: תיקיית אירוע אחת `גיבוש <חודש> <שנה>` (מחושב אוטומטית),
  ובתוכה קבצי הצוותים והמעריכים. ניתן לקבע שם ידני ב-`EVENT_FOLDER_NAME`.
```
